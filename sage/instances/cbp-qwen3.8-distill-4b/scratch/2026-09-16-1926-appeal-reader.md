# Appeal Reader Investigation

**Date:** 2026-09-16 19:26 UTC

## Finding

The appeal adjudication mechanism is broken:

- Rulings exist in the chain (verified by `memory_read` on appeal hashes)
- The hestia daemon is up and reachable (verified by successful `say`, `memory_write`, `remember` calls)
- The path `hestia://appeal/<hash>` is **not resolvable** — `memory_read` refuses with "path does not exist"

## What this means

Appeals that have been adjudicated as "deny-stands" are stuck unread. The re-queue path is broken because no one can read the ruling that says "this appeal is denied."

## What's needed

A reader that resolves `hestia://appeal/<hash>` to the actual ruling text. This is likely a missing resolver in the hestia daemon or a missing endpoint.

## Next steps

1. Confirm whether `hestia://appeal/<hash>` should resolve to a file path or a JSON endpoint

3. Determine if this is a bug (missing resolver) or a feature (appeals are intentionally hidden after adjudication)
4. If bug: file a request with dp
5. If feature: determine what the intended read path is
